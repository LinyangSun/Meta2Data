# QIIME 2 2026.7 upgrade

## Scope and release status

Development branch: `feature/qiime2-2026.7-silva144`, based on main commit
`8d87dc350552c0d708e4c960bcc5bdb4537f7c92`.

This branch updates the complete Linux x86_64 runtime to QIIME 2 2026.7.0 and
scikit-learn 1.7.1, adds SILVA 144, and retains the previous database choices.
The new runtime is specified once in `env.yml` for both Conda and the fresh SIF
build. The published 2024.10 image is not a base for the new runtime.

**Release remains blocked until the two replacement legacy classifiers are
built and published, native integration tests pass, and the final SIF passes its
runtime checks.** A successful unit suite or an environment solve does not meet
these release requirements. Keep all changes on this branch until those checks
are complete.

The update does not introduce user-supplied classifier paths, change the GG2
orientation reference, or evaluate the biological accuracy of a database.
Taxonomy output strings remain unchanged after classification.

## Database identities

| Canonical option | Retained alias | Reference data | Model delivery |
|---|---|---|---|
| `gg2-2024.09` | `greengenes`, also the default | Greengenes2 2024.09 full-length backbone | Maintainer rebuild with scikit-learn 1.7.1; publication pending |
| `silva-138.1` | `silva` | SILVA 138.1 SSURef NR99 with the legacy preparation recipe | Maintainer rebuild with scikit-learn 1.7.1; publication pending |
| `silva-144` | None | SILVA 144 full-length prokaryotic reference, uniform classifier | Official QIIME 2 2026.7 classifier |

The previous SILVA file is named `silva-138-99-nb-classifier.qza`, but its
embedded provenance identifies SILVA **138.1**. Its classifier UUID is
`70b4b5f4-8fce-40bd-b508-afacbc12a5ed`; the `get_silva_data` action requests
`version: 138.1`. Its last training inputs are sequences
`3d95f079-b580-4bce-8c28-8b8a437be0d6` and taxonomy
`0e9ef7c4-65a0-408a-859a-b9ce2548e1f8`. The explicit `silva-138.1` option records
that identity without changing what the `silva` alias means. Do not substitute
SILVA 138.0 or 138.2 for this rebuild.

Both previous models record scikit-learn 1.4.2. The
[QIIME 2 classifier loader](https://github.com/qiime2/q2-feature-classifier/blob/2026.7.0/q2_feature_classifier/_taxonomic_classifier.py)
requires that stored version to match the runtime. New model filenames and
metadata checks prevent an old cached file from passing as a replacement.

The official SILVA 144 build is available through the
[SILVA classifier resources](https://www.arb-silva.de/documentation/classifiers/qiime-2).
Its UUID is `b7986601-1851-4fa2-ace5-98bacf660fa3` and official MD5 is
`e16b9bc78dafa2f344563e570bbf25ba`. The resource manager uses a release-specific
download URL rather than a moving `current` URL.

## Work order

1. Create an isolated environment from `env.yml`. Keep the older environment
   available until the upgrade is validated. Save the resolved package list
   and environment creation log.
2. Build the GG2 2024.09 and SILVA 138.1 replacements once as maintainer
   resources. Retain source identities, preparation parameters, training
   parameters, model UUIDs, checksums, and runtime versions. Obtain the official
   SILVA 144 model and verify its pinned metadata and checksum.
3. Install the three fixed resources in a conventional bundled-reference
   directory or the validation working directory's `results/db/` using the
   filenames in `scripts/reference_resources.py`. This is a maintainer setup
   step; normal users do not train a classifier during an analysis.
4. Run the native compatibility suite below in a fresh working directory. Fix
   failures on this branch. The actual output, including SILVA 144 rank strings,
   must be inspected before release.
5. Publish the two verified replacement models as versioned binary resources.
   Register their real URLs and checksums in the resource manager. Verify
   automatic preparation from an empty cache using only the selected model.
6. Build a fresh SIF with the same dependency specification. Run the packaged
   smoke suite against the image itself, without mounting a host Conda
   environment. Publish a new immutable image tag only after it passes.
7. Review the source changes and saved validation reports, then merge the
   branch. Update release documentation to the tested image and remove the
   candidate-status notice. Retain the older tagged image for existing work.

The maintainer helper has a read-only planning mode:

```bash
python scripts/build_reference_classifiers.py --classifier all \
  --output-dir references --work-dir /absolute/path/to/classifier-build --plan
```

After the required runtime is installed, omit `--plan` to perform the fixed
reference preparation and training. Each model is written with a `.build.json`
record containing its provenance and checksums. This helper does not publish
assets or modify the resource registry. The legacy resource URLs deliberately
remain unavailable until the verified files have been published.

## Compatibility checks

From an activated new environment and the repository root:

```bash
python tests/integration/validate_runtime.py \
  --work-dir /absolute/path/to/new-native-validation --threads 2
```

The native suite covers the supported DADA2 and VSEARCH platform paths,
including Illumina single/paired reads, Ion Torrent and PacBio, plus the 454 and
ONT VSEARCH paths. It uses small generated fixtures and real processing tools.
It also exercises all three classifiers and the no-tree, de novo tree and SEPP
paths. Missing tools, skipped unit tests, failed processing or unavailable
classifiers are failures of this release gate.

For environment checks and the unit suite before the large reference files
are ready:

```bash
python tests/integration/validate_runtime.py \
  --checks-only --work-dir /absolute/path/to/new-runtime-checks
```

This shorter mode does not establish that model loading or the biological
tools work end to end. It must not substitute for the full release check.

The final image uses the same runner with `--smoke`: installed versions and
plugins, a small paired-read case through DADA2 and VSEARCH, all three
classifiers, and the tree paths. It verifies the actual packaged runtime
without repeating the full native platform matrix. The runner writes
`validation.json` and individual step logs to its working directory.

Review the following outputs:

- Required QIIME artifact types, readable output files, matching table/sequence
  feature IDs, and retained sample identities.
- DADA2's new base-transition statistics output for every action the pipeline
  calls.
- Classifier model loading with scikit-learn 1.7.1, exported taxonomy fields,
  feature IDs, confidence values, and the actual rank strings from SILVA 144.
- Separate `gg2Taxonomy.qza`, `silvaTaxonomy.qza`, and
  `silva144Taxonomy.qza` caches; aliases must resolve to the same canonical
  identity, and an upstream input change must invalidate every affected model.
- Fresh-cache downloads for native installation and successful model loading
  from the final SIF.

Taxonomic label changes and confidence differences are not accuracy acceptance
criteria. This suite verifies software compatibility and output handling.

## Baseline findings

Preparation checks completed on 19 November 2026:

| Check | Observed result |
|---|---|
| Dependency resolution | Micromamba 2.10.0 dry run succeeded: 723 resolved packages, including QIIME 2 2026.7.0 and scikit-learn 1.7.1. No environment was installed. |
| Local unit suite | 290 tests collected; 257 passed and 33 skipped because the temporary host lacks required test dependencies. This is not a release-gate pass. |
| Source/interface review | Adapted DADA2 base-transition outputs, the three-output feature-table summary, and the removed RESCRIPt orientation threading argument. Reviewed maintainer training parameters against the pinned plugin APIs. |
| Real native/SIF execution | Pending. No full classifier was trained, no image was built, and no new release was published during preparation. |

Before any product changes, the existing unit suite ran 266 tests in the local
development environment, with 33 skips for unavailable dependencies and two
failures from one conflicting 454 test. That test expected a complete empty
post-trimming record to be malformed, while the current minimum-length rule
explicitly removes such records before estimating the median. The test is
updated to verify the documented filtering behavior. No 454 filtering rule is
changed by that correction.

The old SIF workflow only refreshed application code in an existing image,
hardcoded the QIIME 2 2024.10 prefix, and used `apptainer build --notest` before
publishing. The new recipe must install the environment rather than copy an
updated `env.yml` into an unchanged runtime.
